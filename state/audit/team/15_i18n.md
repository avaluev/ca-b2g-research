## 3. Code Patch — Auto `<span lang="ru">` in `render_site.py`

Add the following helper immediately after the `slugify` function (around line 57). The helper wraps any Cyrillic run in the appropriate `lang=` span. A `country` hint allows `"uz"` vs `"ky"` discrimination; default is `"ru"` (covers Russian text in both countries).

```python
import re as _re

_CYRILLIC_RE = _re.compile(r'([Ѐ-ӿ]+(?:\s+[Ѐ-ӿ]+)*)', _re.UNICODE)

def cyrillic_span(text: str, lang: str = "ru") -> str:
    """Wrap Cyrillic runs in <span lang='{lang}'> for AT and search engines."""
    if not text or not _CYRILLIC_RE.search(text):
        return escape(text)
    # escape first, then re-wrap — avoids double-escaping
    escaped = escape(text)
    # re-run on escaped text (Cyrillic chars survive html.escape unchanged)
    return _CYRILLIC_RE.sub(
        lambda m: f'<span lang="{lang}">{m.group(1)}</span>',
        escaped
    )
```

Replace relevant `escape(...)` calls in table cells that output known Cyrillic fields:

| Current call | Replace with |
|---|---|
| `escape(d.get('number') or '')` in `decrees_page` | `cyrillic_span(d.get('number') or '', lang='ru' if country=='UZ' else 'ky')` |
| `escape(i.get('name_ru') or '')` in `institutions_page` | `cyrillic_span(i.get('name_ru') or '', lang='ru')` |
| `escape(i.get('name_local') or '')` (if surfaced) | `cyrillic_span(i.get('name_local') or '', lang='uz' if i.get('country')=='UZ' else 'ky')` |
| `escape(t.get('title') or '')` in `procurement_page` fallback path | `cyrillic_span(t.get('title') or '', lang='ru')` |
| `escape(t.get('name') or '')` in `trends_page` | `cyrillic_span(t.get('name') or '', lang='ru')` |

## 4. Russian-Summary Page Proposal

The target audience — regional decision-makers in Uzbekistan and Kyrgyzstan — reads Russian far more readily than English. A lightweight `/ru/` mirror of three pages adds the most value for the least maintenance overhead.

**Proposed pages** (render from the same knowledge graph, separate template):

| URL | Content | Priority |
|---|---|---|
| `/ru/` | Home page translated: headline KPI grid, what/how/who, Russian-language source note | High |
| `/ru/methodology/` | Methodology table + source priority in Russian | Medium |
| `/ru/initiatives/` | Top 25 initiatives table with Russian `short_name` / `one_liner` where available; fall back to EN | High |

**Implementation approach** — add a `render_page_ru()` variant in `render_site.py` that:
1. Sets `<html lang="ru">` instead of `<html lang="en">`.
2. Uses a `TRANSLATIONS` dict at module top for nav labels and static prose strings (keep the dict in the same file, ~80 lines).
3. For data fields, prefers `title_original` / `name_ru` over English equivalents.
4. Emits `<meta property="og:locale" content="ru_RU">` instead of `en_US`.

This is a one-person, one-day task. Avoid full bilingual mirroring of all 15 pages — maintenance cost outweighs benefit for the procurement/people/donors deep-dives that regional readers are unlikely to browse.

## 6. Currency / Date / Number Style Guide

**Dates**
- Storage and `<time datetime>` attribute: ISO 8601 (`2026-05-04`). Already correct in knowledge graph.
- Display text: `2026-05-04` (year-month-day). The current render passes ISO dates through `escape()` directly — this is correct; do not convert to `5/4/26`.
- Wrap all date cells: `<time datetime="2026-05-04">2026-05-04</time>` for AT and structured data. Currently bare text.

**Currency**
- Primary display: `$8,000,000` (USD, comma-separated). Already correct in `donors_page` and `initiatives_page` via `:,.0f`.
- Local-currency parenthetical for values > $1 million on the procurement page: `$8,000,000 (102.4 Bn UZS)`. The knowledge graph stores both `estimated_value_usd` and `value_original` + `currency_original` — the data is present, display is not.
- Do not show local currency for donor budgets (always USD in agreements).

**Numbers**
- Comma thousands separator throughout. Verified consistent in current render.
- Do not use period as thousands separator (German convention) — nowhere present, confirm on future edits.

## 7. Proper-Noun Transliteration — Surface Proposal

The schema holds `full_name_latin`, `full_name_ru`, and `full_name_local` for every person. The institutions table already renders `name_ru`. Recommended display for the People page:

<td>
  Sherzod Shermatov
